Pipeline

How a prediction actually gets made, end to end. This page is documentation, not a live process.

  1. 01

    Data ingestion

    Raw CSV is loaded and column names are standardized.

  2. 02

    Data validation

    Fail-fast checks for missing columns, bad types, duplicates, and out-of-range scores.

  3. 03

    Feature engineering

    Only demographic and preparatory columns are used. Reading and writing scores are deliberately excluded, see Model Performance.

  4. 04

    Preprocessing

    Scaling and one-hot encoding via an explicit allow-list of permitted columns.

  5. 05

    Training & tuning

    Linear Regression and Random Forest are compared; Random Forest is tuned with RandomizedSearchCV.

  6. 06

    Explainability

    SHAP computes an exact, per-prediction breakdown of each feature's effect.

  7. 07

    Serving

    A FastAPI endpoint exposes the trained model, validated by Pydantic, to this dashboard.

About

The story behind this project, and what it's actually demonstrating.

This project began as a straightforward regression task: predict a student's math score from their background. Partway through, it turned out an earlier version was quietly cheating, using the student's reading and writing scores, from the same exam sitting, as inputs. That produced a suspiciously good RMSE of about 5.3. Once removed, the honest RMSE landed closer to 14.2. That correction, not the model itself, is the actual center of this project.

Everything past that point exists to make the prediction trustworthy rather than just accurate-looking: SHAP explains every individual prediction, and a subgroup fairness audit checks whether that reasoning holds up consistently across demographic groups, rather than assuming it does.

Stack

Python, pandas, scikit-learn, SHAP, FastAPI, Pydantic, with this dashboard as plain HTML, CSS, and JavaScript, no framework or build step.
